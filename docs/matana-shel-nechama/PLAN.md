## 2. ארכיטקטורה

```
[נייד / דפדפן · PWA · RTL]
        │
        ▼
Next.js 15 (App Router, TypeScript, Tailwind) — Vercel
 ├─ /            דפים ציבוריים (SSR/ISR)
 ├─ /gift        אשף רכישה (Client + Server Actions)
 ├─ /wallet      ארנק משפחתי (Auth)
 ├─ /provider    פורטל ספק (Auth + provider_members)
 ├─ /admin       ניהול (Auth + role=admin)
 └─ /api/*       Route Handlers: תשלום (sandbox), webhooks, מימוש, QR
        │  supabase-js (anon + RLS)        │  service role (שרת בלבד)
        ▼                                  ▼
Supabase (פרויקט ייעודי, eu-central-1)
 ├─ Postgres + RLS לפי תפקיד
 ├─ פונקציות SQL (security definer): issue_voucher, claim_voucher,
 │    redeem_voucher, reverse_redemption, redeem_benefit — אטומיות, אידמפוטנטיות
 ├─ Auth: Magic Link באימייל (MVP); OTP בטלפון בשלב ג'
 ├─ Storage: לוגו ספקים, תמונות שירותים
 └─ voucher_ledger + audit_log (append-only)
```

**עקרונות מחייבים**
- כל כסף באגורות (`int`). אין float.
- שובר נוצר **רק** בטרנזקציה שמסתיימת ב-`payments.status='captured'`. במצב בדיקה הסולק הוא `sandbox` וכל רשומה מסומנת `is_test=true` ומוצגת עם תווית "סביבת בדיקה".
- מימוש = `select … for update` על השובר + בדיקות + כתיבה ל-`redemptions`, `voucher_ledger`, `audit_log` — בטרנזקציה אחת, עם `idempotency_key` ייחודי. לחיצה כפולה/רשת איטית לא יוצרות מימוש כפול.
- הלקוח לעולם לא כותב ל-`payments`, `vouchers`, `voucher_ledger`, `audit_log`.
- פרטי כרטיס אשראי לא עוברים דרך השרת שלנו ולא נשמרים — גם לא בעתיד (טופס מוטמע של הסולק).
- ספקי הדגמה (`is_demo=true`) מופיעים רק בסביבת בדיקה ותמיד עם תווית "לדוגמה". בפיילוט נמחקים.
- i18n: כל המחרוזות בקובץ `messages/he.json` מהיום הראשון; `locale` בפרופיל.

## 4. עיצוב דף הבית

ראו את ההדמיה בדף התכנון הוויזואלי (קובץ `design-preview.html` באותה תיקייה).

**שפה חזותית**
- צבעים: נייבי עמוק `#182A4A` / `#0F1C33`, שמנת `#F7F2E8`, זהב עדין `#C9A75B`, לבן. ללא שחור טהור, ללא אפור קר.
- טיפוגרפיה: כותרות **Frank Ruhl Libre** (סריף עברי, יוקרתי ושקט), גוף **Heebo**. שתיהן ב-Google Fonts, תומכות עברית.
- תמונות: אור נר רך, פרחים לבנים, טקסטיל, שולחן ערוך. ללא בתי עלמין, ארונות או סמלי אבל כבדים.
- טון: קצר, חם, לא שיווקי. אין "מבצע", אין טיימרים, אין פופ-אפים.

**מבנה הדף (נייד תחילה)**
1. **כותרת עליונה** — לוגו, תפריט, "כניסה".
2. **Hero** — "דרך לתת, גם כשאין מילים." + משפט הסבר + שני כפתורים: *שליחת מתנה למשפחה* (ראשי, זהב) ו-*צפייה בהטבות* (משני, קווי).
3. **איך זה עובד** — 3 צעדים: בוחרים סכום → המשפחה מקבלת קישור → מממשים אצל ספקים מאושרים.
4. **קטגוריות שירותים** — 6 כרטיסים עם תמונה: קייטרינג וארוחות לשבעה · אוהלים וציוד · ניקיון ועזרה בבית · מצבות והנצחה · פרחים ומוצרי זיכרון · יום השלושים ואזכרות.
5. **שקיפות** — פס קצר: "המתנה מגיעה במלואה למשפחה. העמלה נגבית מהספק. ללא דמי טיפול לנותן המתנה." (נוסח סופי לפי החלטת מודל כספי).
6. **מתנה קבוצתית** — "מתאחדים לתת יחד" + כפתור.
7. **למעסיקים** ו-**לספקים** — שני כרטיסים זה לצד זה.
8. **שאלות נפוצות** — אקורדיון, 5 שאלות.
9. **פוטר** — אודות, תנאי שימוש, פרטיות, יצירת קשר, קרדיט עדין "מופעל על ידי אבלות ישראל".

## 5. מבנה בסיס הנתונים

הסכמה המלאה: `schema-draft.sql`. תקציר הישויות:

| קבוצה | טבלאות |
|---|---|
| משתמשים | `profiles`, `user_roles` |
| קטלוג | `categories`, `providers`, `provider_categories`, `provider_members`, `provider_services`, `benefits` |
| ארנק | `wallets`, `wallet_members`, `wallet_invites`, `benefit_cards` |
| כסף | `orders`, `payments`, `vouchers`, `redemptions`, `voucher_ledger` (append-only), `benefit_redemptions`, `refunds` |
| התחשבנות | `settlements`, `settlement_items` |
| מעסיקים (שלב ד') | `employers`, `employer_members` |
| תפעול | `issues`, `audit_log` (append-only) |

**מחזור חיי שובר**
`orders.draft → pending_payment → paid` ⇒ `issue_voucher()` ⇒ `vouchers.pending` ⇒ המשפחה פותחת קישור ⇒ `claim_voucher()` ⇒ `active` ⇒ `redeem_voucher()` ×n (ledger) ⇒ `redeemed` / `expired`.

## 7. החלטות שדרושות ממך לפני פיתוח

1. **Supabase**: לאשר יצירת פרויקט חדש בשם `matana-shel-nechama` (eu-central-1, חינמי בשלב זה) בארגון הקיים. חלופה: להשתמש בפרויקט הלא-פעיל `avelut-os-staging` — לא מומלץ, מערבב מוצרים.
2. **מיקום הקוד**: לפתח בתיקייה `apps/matana/` בתוך מאגר זה (ענף `ccr-78b71e28-ny1237`), עם המלצה להעביר למאגר ייעודי לפני הפיילוט. חלופה: ליצור מאגר חדש כבר עכשיו (דורש גישה).
3. **מודל כספי לתצוגה**: ברירת מחדל מוצעת — נותן המתנה משלם רק את סכום המתנה (0 דמי שירות), הפלטפורמה גובה עמלה מהספק במימוש (אחוז פרמטרי, ברירת מחדל 10%). זה משפיע על נוסחי שקיפות באתר.
4. **אימות משפחה ב-MVP**: Magic Link באימייל + קישור קבלה חתום. OTP ב-SMS/WhatsApp רק בשלב ג' (דורש ספק הודעות).
5. **תוקף שובר**: הצעה — 24 חודשים מהנפקה, ניתן לשינוי במנהל.

לאחר אישור חמש ההחלטות (או תיקונן) — מתחילים ב-B0.
